## Defects found

1. **Text is garbled: the glyph lookup is wrong.** The soft-key captions "PRG -", "PRG +", "COMBI", "COMPARE", "PAGE -", "PAGE +" render as "Z1Q -", "Z1Q +", "MYWLS", "MYWZK10", "ZKQO -", "ZKQO +"; the brand "KORX" renders as "XKWO"; the label "PROGRAM" and program names are unreadable. The letters are consistently substituted, so the character -> glyph index mapping (the "A-Z core plus fold" scheme) is off. Replace it with a plain, obviously-correct scheme: a table indexed directly by `ch - 32` for ASCII 32..126 (95 entries, 5 bytes each = 475 bytes; with a 7th/8th row bit packing, or 5x7 column bytes, whichever you prefer), **no case folding**. Real program names are mixed case with digits and punctuation (`Piano16'`, `Brass1&2`, `E.Piano1`), so lowercase and punctuation must render correctly. The font may be up to ~1 KB.
2. **Font test card.** Add a way to render a font test screen (for example a build flag `-DKORX_FONT_TEST` that makes `vibe_wasm_draw` show it, or a special event) that draws ALL printable ASCII 32..126 at scale 1 and at scale 3 plus the strings `PRG - PRG + COMBI COMPARE PAGE - PAGE + KORX Piano16' Brass1&2 E.Piano1 0123456789`. Render it to `shots/font_test.png`. The human will inspect it, so make the glyphs real, recognisable 5x7 letterforms of your own design (no copying of existing ROM fonts).
3. **`03_osc.png` is identical to `01_program.png`.** The scripted navigation did not reach the OSC page. In `render_shots.bat` use these model events: K1..K6 buttons are ids 10..15 (button type 3, send down=1 then down=0); K2 (id 11) jumps to the model's group 1; `e:3,11,1,0` then `e:3,11,0,0`; the Hub's render tool needs `a:3` after events. Each shot must differ from the Program shot. Add a check in `verify_shots.mjs` that no two shots are pixel-identical, and print which group name each shot expects.
4. **Palette is wrong for an LCD.** The soft-key row and the edit columns are bright yellow-green, and bars are brown and blue. A believable monochrome LCD has only two or three tones: dark "ink" pixels on the pale blue-green backlight (and a slightly darker green for inactive/grid, light-on-dark for inverse video). Use exactly: `BG` pale blue-green, `INK` very dark blue-grey, `GRID` slightly darker than BG, `INV_BG` = INK and `INV_FG` = BG. Soft keys: dark bezel-grey buttons with LCD-green legends (like the physical keys under the display), or LCD-style framed cells with INK text, not yellow. Bars: INK blocks on a GRID trough (an LCD "slider"), no brown, no blue. Keep `KORX_DARK_MODE` as the alternate (dark ink-on-dark with a bright green phosphor).
5. **Edit page layout.** The four columns must read as four LCD cells in the Hub's 115 px columns: parameter name (small), value (large, scale 2), slider bar underneath; the first (current) column in inverse video. Do not fill the columns with a separate colour. The envelope graph on EG pages goes BELOW the four cells inside a thin bordered area, with INK strokes (2 px wide), not a thin blue line. The VDF page curve likewise.
6. **Play screens.** Program play: bank/number and the name at scale 3 (must now be legible), plus one line with OSC mode / assign / OSC 1 multisound name (from the model's params for the first group), and the voice-use and L/R meter bars in INK. Keep the eight-timbre strip on the combination screen: per row `A..H`, program number, program name (legible), level slider, and `ON`/`--`.
7. Keep everything integer-only, no heap, same public API, same Hub touch geometry (soft keys y 282..319, four 115 px columns from x=10).
